# Experimental protocol

## Dataset and exact split

Use DAVIS 2017 Semi-supervised TrainVal 480p downloaded from the [official DAVIS page](https://davischallenge.org/davis2017/code.html). The exact split is defined by the official sequence names in `ImageSets/2017/train.txt` and `ImageSets/2017/val.txt` packaged with that release. The loader records the full names it reads in each experiment's `metadata.json`; the split is not copied into a hard-coded source list. If the official lists are located under a supported equivalent directory, the same file stems are used.

The run is invalid if either split file is absent/empty, if a sequence appears in both files, if a training name is outside the official train list, if an evaluation name is outside the official validation list, or if calibration candidate metadata contains a validation sequence. The validation list is not used to fit the confidence model or select the configured operating threshold. This repository's current DAVIS TrainVal configuration does not supply an independent labeled test split; the reported validation results are not described as final test results. The manifest records the resolved dataset root and exact train/validation names.

## Data and inference separation

All valid ground-truth masks are treated as detections for every method. Frame image/mask pairs are joined by filename stem. Feature extraction may process both train and validation images and persist embeddings, but that does not make validation labels model inputs. At inference, each detection contains a local frame ID, embedding, center, box, and area. Ground-truth labels remain in separate bookkeeping used for calibration targets and after-the-fact evaluation.

Training candidate states are generated by replaying training sequences with thresholded cosine matching at the configured cosine cutoff. This gives training replay the same ability to reject a weak candidate and create a new identity as selective inference. The candidate correctness target compares a predicted memory identity's previous ground-truth owner with the current detection's ground-truth label. Only the six association features enter logistic regression. Class weighting, scaling, maximum iterations, random state, memory duration, feature schema, and replay policy are stored with the calibrator. Replay is closer to selective inference than forced matching, but the learned probability policy can still create different memories and later pair features, especially over long sequences.

## Train and validation procedure

1. Read official split lists and reject overlap.
2. Extract frozen DINOv2 object embeddings for selected train/validation frames and cache them with source image/mask content digests, preprocessing settings, and the exact checkpoint state-dict SHA-256.
3. Generate train candidate pairs from training sequences only.
4. Fit StandardScaler and unweighted logistic regression on train candidate vectors/labels. The validation sequence list is passed only to an overlap guard; the metadata states `validation_sequences_used_for_fit: []`. Any non-null class weighting is an explicitly configured sensitivity analysis because it changes the fitted class prior. The fitting API rejects overlaps with a reserved test sequence set if one is supplied.
5. Run each baseline and the selective method independently on the same validation sequences, detections, cached features, and default 30-missing-frame memory rule.
6. Compute tracking/association metrics and calculate pooled and per-sequence Brier, ECE, and reliability only for logistic probability estimates on validation candidate pairs. Report the candidate-pair count for each calculation. Empty evaluation sets have undefined Brier/ECE; single-class sets retain computable Brier/ECE but are marked as having limited class support. Do not assume probabilities are calibrated from the logistic model alone.
7. Export pair-level candidate outcomes and a separate one-row-per-detection decision table (including no-candidate detections), sequence-level and aggregate metrics, candidate labels, candidate-pair and assignment-level precision/coverage analyses, full-tracking confidence-threshold results, split names, configuration, software/GPU metadata, and figures.

No validation threshold is selected. The configured confidence threshold is used for the primary result. The default full-tracking replay thresholds are 0.3, 0.5, and 0.7, plus the configured operating threshold if it is not already listed. The candidate-pair curve thresholds pairs independently; the assignment-level curve reruns the one-to-one optimization on logged frame states; the full-tracking sweep replays validation sequences from fresh memory at each threshold. These are validation diagnostics, not operating-point selection or test results. If a future study needs a selected operating threshold, it must use a predeclared selection set and retain an independent labeled test set for final evaluation.

## Ablations

- **Appearance/motion:** appearance only; appearance plus center displacement; appearance plus center displacement and box IoU. The same masks, sequence order, memory gap, and fixed score cutoff are used.
- **Probability analysis:** compare fixed raw-cosine rejection with logistic-probability selective decisions. Brier/ECE apply only to the probability model. No claim is made that logistic regression automatically calibrates itself.
- **Memory duration:** 5, 15, 30, and 60 missing frames. Fit a separate confidence model on training candidates with the corresponding memory duration; use the matching duration on validation.
- **Confidence threshold:** report candidate-pair and frame-level assignment curves plus full-sequence tracking metrics at configured cutoffs; do not choose a best point and call it an unbiased test result.
- **Mask-defined absence:** group same-identity reappearances by the count of complete, valid annotated frames where the GT object is absent. Masks do not identify whether absence is caused by occlusion or leaving the view. Gaps crossing missing/invalid input frames are excluded.

Artificial observation removal is not implemented. Its results must be a separate controlled experiment if added later.

## Smoke tests and full evaluation

Smoke mode prefers a small number of multi-object sequences inside each official split, then limits frames per sequence. It exercises cache, candidate generation, fitting, tracking, metrics, and export; it is not a publication result and must be labeled as smoke-test output. Full evaluation uses every sequence in the official split. The manifest records selected names and frame limits for either mode.

The smoke feature cache must be extracted with the same smoke sequence/frame selection used by the experiment. Full experiments require complete cached features for all selected frames. Missing features stop a run with a path and object label; they are never silently substituted.

## Reproducibility and outputs

Python, NumPy, PyTorch, CUDA, and scikit-learn randomness are seeded from `experiment.random_seed` and estimator `random_state`. CUDA backend determinism settings are enabled where available. Experiment directories are unique by default and preserve the config, metadata, train/validation lists, calibrator, candidate predictions, per-sequence calibration and tracking results, aggregate metrics, logs, and PNG/PDF figures. Git hash is recorded when the workspace has valid Git metadata; otherwise it is `null`.
